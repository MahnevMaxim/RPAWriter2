# 18. Deploy и анализ логов

Эта глава описывает сборку и публикацию роботов, чтение ошибок компиляции и окна вывода, анализ
логов и перехват runtime-исключений.

## Deploy (публикация)

Кнопка **Deploy** на панели инструментов вкладки Chat собирает решение в конфигурации **Publish**.

Перед запуском расширение проверяет:

1. открыто ли решение;
2. есть ли в решении RPA-проект;
3. настроена ли конфигурация **Publish**.

Имя проекта для публикации задаётся настройкой **Deploy project name** (вкладка Settings → General).
Вводится без расширения `.csproj`. Если поле пустое — расширение ищет RPA-проект автоматически.

> Если конфигурации Publish нет, создайте её: `Build → Configuration Manager`.
> Подробнее — [Диагностика и FAQ](09-troubleshooting.md).

Результат публикации показывается уведомлением (баннером) с возможностью закрыть или отправить
в чат. Успешные уведомления автоматически закрываются через заданный интервал (см.
[Вкладка Controls](07-controls.md) → Notifications).

## Сборка Release

Агент может запустить Release-сборку открытого решения инструментом `build` (см.
[Инструменты агента](15-agent-tools.md)). После сборки решение переключается обратно в конфигурацию
Debug.

## Чтение ошибок компиляции

- Кнопка **Send errors** на панели вкладки Chat читает ошибки из **Error List** Visual Studio и
  отправляет их в чат для анализа агентом. Если ошибок нет — сообщает об этом.
- Агент может прочитать Error List самостоятельно инструментом `read_errors`.

Каждая ошибка включает код, сообщение, файл, строку/колонку, проект и уровень серьёзности
(Error / Warning / Message).

## Чтение окна вывода

Агент может прочитать текст **окна вывода Visual Studio** (панели Build / Debug / General)
инструментом `read_output`. Кнопка **Analyze logs → From Visual Studio Output window** делает то же
самое: формирует промпт из текста окна вывода и отправляет его в чат на анализ.

## Анализ логов

Кнопка **Analyze logs** открывает область анализа с двумя источниками:

| Источник | Что делает |
|---|---|
| **From Visual Studio Output window** | Анализирует текст окна вывода VS |
| **From production servers** | Читает логи с production-серверов через подключённые провайдеры |

Анализ выполняется моделью `LogAnalyzer`: логи разбираются на записи (уровень, источник, сообщение,
параметры), формируется сводка с ошибками и предупреждениями, и промпт отправляется агенту.

## Провайдеры production-логов

Логи с production-серверов читаются через подключаемые провайдеры, реализующие интерфейс
`IProdLogProvider`. Каталог с DLL провайдеров задаётся настройкой **Log providers directory**
(вкладка Settings → RPA). Расширение сканирует каталог, находит все типы с публичным
конструктором без параметров, реализующие `IProdLogProvider`, и использует их.

Пример провайдера лежит в проекте **Examples.LogProvider** — его можно взять за основу для
собственного провайдера.

## Перехват runtime-исключений

Расширение следит за отладчиком Visual Studio: когда отладка останавливается на исключении
(«exception thrown» / «exception not handled»), оно захватывает объект исключения через
псевдопеременную отладчика `$exception` (включая всю цепочку `InnerException`), тип, сообщение и
место остановки.

- Если включена настройка **Auto-capture runtime exceptions** (Settings → General, по умолчанию вкл.),
  исключение автоматически отправляется в чат агенту.
- Иначе последнее захваченное исключение можно отправить вручную командой контекстного меню
  **Send exception to RPA Writer**.

Одно и то же исключение не захватывается повторно в течение короткого окна (2 секунды).

## Команды контекстного меню Visual Studio

Расширение добавляет в контекстные меню редакторов команды:

| Команда | Где доступна | Что делает |
|---|---|---|
| **Send error to chat** | Error List | Отправляет выбранную ошибку в чат |
| **Send to RPA Writer** (selection) | Редактор кода, XAML-редактор | Отправляет выделенный текст в чат |
| **Send exception to RPA Writer** | Редактор кода, XAML-редактор | Отправляет последнее захваченное исключение в чат |
