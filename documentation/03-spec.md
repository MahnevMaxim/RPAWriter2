# 3. Вкладка Spec

Вкладка **Spec** предназначена для работы со спецификацией (техническим заданием): импорт, декомпозиция на задачи, поиск похожих решений, аудит безопасности роботов и быстрый доступ к файлам `docs` решения. Конвертация роботов вынесена на отдельную [вкладку Converter](11-converter.md).

## Кнопки

| Кнопка | Что происходит при нажатии |
|---|---|
| **Import spec** | Открывает диалог выбора ТЗ (`.docx`, `.doc`, `.xlsx`, `.xls`, `.txt`, `.md`), читает его, декомпозирует на задачи (через AI) и сохраняет структурированные `spec.md` и `tasks.md` в папку `docs` решения. |
| **Generate algorithm** | Генерирует по `spec.md` три независимых черновика алгоритма (`alg-1.md`, `alg-2.md`, `alg-3.md`), согласует их и создаёт итоговый `alg.md` и список вопросов `questions.md` в папке `docs` решения. Файлы алгоритмов перезаписываются без подтверждения. |
| **Generate robot** | Генерирует робота (XAML + C#) из импортированной спецификации и сохраняет рядом с ней. Если спецификация не импортирована — выводит подсказку. |
| **Find similar** | Ищет в базе знаний задачи, похожие на текущую спецификацию. |
| **Robot security audit** | Запускает статический аудит безопасности найденных роботов (см. ниже) и создаёт отчёт `docs/security_audit.md`. |
| **Convert md to docx** | Открывает диалог выбора Markdown (`.md`/`.markdown`) и конвертирует текст и картинки в Word `.docx` рядом с исходным файлом. |
| **Clear** | Очищает область вывода спецификации. |
| **Copy all** (иконка) | Копирует весь вывод спецификации в буфер обмена (появляется, когда есть вывод). |

## Импорт ТЗ (Import spec) — пошагово

1. Проверяется, что открыто решение (иначе — предупреждение).
2. Открывается диалог выбора файла.
3. Проверяется, не заблокирован ли файл другим приложением (Word/Excel).
4. Файл читается (`OpenXmlDocumentReader` для `.docx`/`.xlsx`, NPOI для legacy `.doc`/`.xls`, текст для `.txt`/`.md`).
5. Создаётся/обновляется `docs/spec.md` (структурированный markdown).
6. AI декомпозирует ТЗ на задачи, создаётся `docs/tasks.md`.
7. Спецификация и список задач отображаются в области вывода.

Если `spec.md`/`tasks.md` уже существуют, появится диалог: перезаписать полностью, найти расхождения и предложить частичное исправление, либо оставить без изменений.

## Генерация алгоритма (Generate algorithm) — пошагово

1. Проверяется, что открыто решение (иначе — предупреждение).
2. Определяется источник ТЗ: текущая импортированная спецификация либо файл `docs/spec.md` (если импорт ещё не выполнялся).
3. AI три раза независимо генерирует черновик алгоритма (Markdown: пошаговый текст, диаграмма Mermaid, древовидная структура с переходами) → `docs/alg-1.md`, `docs/alg-2.md`, `docs/alg-3.md`.
4. AI сверяет `spec.md` с тремя черновиками, находит противоречия, генерирует итоговый правильный алгоритм и список вопросов по ТЗ.
5. Результат сохраняется в `docs/alg.md` (итоговый алгоритм) и `docs/questions.md` (вопросы).

Файлы алгоритмов перезаписываются при повторном запуске без диалога подтверждения.

## Конвертация Markdown → Word (Convert md to docx) — пошагово

1. Открывается диалог выбора файла `.md`/`.markdown`.
2. Markdown разбирается (Markdig): заголовки, абзацы, списки, цитаты, код-блоки, таблицы.
3. Изображения `![](…)` читаются относительно папки исходного файла и вставляются в документ (png/jpg/gif/bmp/tiff; svg/emf/wmf пропускаются).
4. Рядом с исходным файлом создаётся `.docx` с тем же именем; в выводе указывается число абзацев, изображений и таблиц.

## Аудит безопасности (Robot security audit)

1. Определяется каталог с решениями роботов: каталог открытого решения либо выбранный вручную каталог.
2. Ищутся решения-роботы вида `RPA-<номер>.sln/.slnx` — как в самом каталоге, так и в соседних папках на том же уровне, имя которых начинается с `RPA-` (в верхнем регистре). Это позволяет сканировать открытое решение вместе со всеми соседними роботами.
3. Запускается статический анализ каждого робота в соответствии с режимом настройки **Security audit mode** (Full или Passwords & logins only).
4. По завершении создаётся и открывается отчёт `docs/security_audit.md`; ход и сообщения отображаются в экспандере **Security audit** (статус, прогресс, список найденных решений).

Подробнее о режиме аудита — в настройке **Security audit mode** на [вкладке Settings](05-settings.md).

## Быстрый доступ к ТЗ (экспандер docs)

Экспандер **docs** под кнопками показывает файлы папки `docs` открытого решения (`spec.md`, `tasks.md`, `alg.md`, `questions.md`, отчёты и т.д.). Markdown-файлы кликабельны и открываются в Visual Studio. Список обновляется при раскрытии экспандера.

> Конвертация роботов (UiPath → WF и PIX → WF) вынесена на [вкладку Converter](11-converter.md).

## Область вывода

Под кнопками находится прокручиваемая область вывода, куда попадают:

- текст импортированной спецификации и список задач;
- сообщения о созданных/перезаписанных файлах.

## Заметки

- Импорт доступен только при открытом решении (файлы `docs/spec.md` и `docs/tasks.md` создаются в папке решения).
- Если файл ТЗ открыт в Word/Excel, импорт будет остановлен с сообщением «файл заблокирован».
