# 2. Вкладка Chat

Вкладка **Chat** — главный интерфейс взаимодействия с агентом. Здесь ведётся диалог, выбирается режим работы, прикрепляются файлы, анализируются логи и управляется контекстное окно модели.

## Области вкладки

Сверху вниз:

1. Панель инструментов (кнопки действий).
2. Панель создания робота (появляется, когда решение не открыто).
3. Панель коммита (появляется по кнопке **commit**).
4. Закреплённый заголовок последнего сообщения + индикатор контекстного окна.
5. Список сообщений.
6. Поле ввода с кнопками вложений/отправки/микрофона/очистки.
7. Селектор режима + нижние кнопки (**Compact now**, **Memory bank**, **Permissions**, **Docs**, **Do it!!!**).

## Панель инструментов

| Кнопка | Что происходит при нажатии |
|---|---|
| **New chat** | Начинает новую беседу. Текущий диалог сохраняется в истории. |
| **history** | Переключает окно на список сохранённых бесед (вид «История»). |
| **commit** | Открывает панель коммита: ввод сообщения, авто-генерация и коммит в git (ветка `dev`). |
| **deploy** | Собирает решение в конфигурации **Publish** (предварительно проверяет наличие открытого решения, RPA-проекта и конфигурации Publish). |
| **Analyze logs** | Открывает область анализа логов: локальные логи, окно вывода VS или логи с production-серверов. |
| **send errors** | Читает ошибки компиляции из Error List и отправляет их в чат для анализа агентом. Если ошибок нет — сообщает об этом. |
| **copy** | Копирует весь текущий диалог в буфер обмена. |

## Панель «Create robot» (создание робота по шаблону)

Появляется, когда решение не открыто, и содержит:

- поле **Robot number** — номер робота (только цифры);
- кнопку **Create robot**.

При нажатии **Create robot** создаётся решение с именем `RPA-<номер>` на основе шаблона робота (настройки **Robot solutions directory** и **Robot template file name**), процесс и результат выводятся в окно вывода VS.

## Панель коммита

| Элемент | Назначение |
|---|---|
| Поле **Commit message** | Текст сообщения коммита |
| Кнопка **Commit** | Выполняет коммит в git на ветке `dev` (только если текущая ветка — `dev`) |
| Кнопка **Auto-generate message** | Автоматически формирует сообщение коммита по изменённым файлам (через AI) |

## Закреплённый заголовок и контекст

Сверху над списком сообщений закрепляется последнее сообщение (свёрнуто в одну строку):

- кнопка **развернуть/свернуть** — показывает/скрывает полный текст закреплённого сообщения;
- кнопка **✕ (Close chat)** — закрывает текущую беседу и показывает историю;
- полоса **Context window** — визуальная индикация заполнения контекстного окна модели;
- текст **Context window: N / M** — оценка использованных токенов контекста.

> 📘 Подробнее об автосжатии, восстановлении при переполнении, токенах/стоимости и Memory Bank — см. [Управление контекстом и память](10-context.md).

## Индикатор чекпоинта

Когда агент делает снимок файлов (в начале задачи или перед правкой файла), в списке сообщений появляется индикатор чекпоинта: короткий хеш коммита, время и кнопки:

| Кнопка | Что делает |
|---|---|
| **Compare** | Открывает отдельное окно с графическим diff изменённых файлов относительно этого чекпоинта (ничего не добавляет в чат). |
| **Restore** | Спрашивает подтверждение и откатывает файлы к этому чекпоинту (результат пишется в лог, в чат не добавляется; ошибка показывается красным баннером сверху). |

Подробнее о механизме, хранении и условиях работы: [Чекпоинты](12-checkpoints.md).

## Поле ввода

| Элемент | Назначение |
|---|---|
| **Поле ввода** | Многострочный текст сообщения. `Enter` — отправить, `Ctrl+Enter` — перевод строки |
| **📎 Attach** | Прикрепить файл или изображение (текстовый файл или картинка) |
| **➤ Send** | Отправить сообщение агенту |
| **🎤 Mic** | Начать/остановить голосовой ввод (см. настройки распознавания речи) |
| **🧹 Clear** | Очистить поле ввода |
| **Cancel** | Отменяет текущий выполняющийся запрос (видна во время работы агента) |

Прикреплённые файлы отображаются над полем ввода в виде чипов с кнопкой **✕** для удаления.

## Селектор режима

| Режим | Что может агент |
|---|---|
| **Plan** | Только чтение и анализ. Изменяющие инструменты недоступны. Ответ выделяется как «план». |
| **Act** | Полный доступ: чтение, изменение файлов, создание роботов, сборки. Ответ выделяется как «действие». |
| **Help** | Агент поддержки: отвечает по встроенной документации, без инструментов. Подробнее в [режиме Help](08-help-mode.md). |

Переключение режима фиксируется в беседе сообщением `Mode: …`.

## Нижние кнопки

| Кнопка | Что происходит при нажатии |
|---|---|
| **Compact now** | Принудительно сжимает (суммирует) историю беседы, освобождая контекстное окно. |
| **Memory bank** | Подставляет в поле ввода команду агенту обновить банк памяти проекта (видна только когда банк памяти включён в настройках). |
| **Permissions** | Открывает оверлей прав агента (см. ниже). |
| **Docs** | Открывает встроенную документацию (страница оглавления). |
| **Do it!!!** | Подставляет текст `Do it!!!` и отправляет его агенту (быстрая команда «сделай»). |

## Права агента (Permissions)

Оверлей содержит флаги, разрешающие категории инструментов:

- **Read files** — чтение файлов, спецификаций, базы знаний, логов, ошибок;
- **Edit files** — запись/правка файлов, генерация роботов, импорт базы знаний;
- **Execute commands (PowerShell)** — выполнение shell/PowerShell-команд;
- **Web fetch** — загрузка веб-ресурсов;
- **MCP** — вызов инструментов MCP.

## История бесед

Вид **history** показывает сохранённые беседы:

- **New chat** — начать новую беседу;
- **Clear history** — очистить всю историю;
- карточка беседы — открыть беседу;
- кнопка **✕** на карточке — удалить конкретную беседу.

## Анализ логов

Область анализа логов (открывается кнопкой **Analyze logs**) содержит:

- **From Visual Studio Output window** — прочитать и проанализировать текст окна вывода VS;
- **From production servers** — работа с логами production-серверов;
- **Load tasks** — загрузить список задач;
- **Analyze logs** — запустить анализ выбранных логов;
- таблица записей лога: **Timestamp**, **Level**, **Source**, **Message**.

## Перехват исключений при отладке (runtime exceptions)

Когда отладчик Visual Studio останавливается на исключении (thrown или not handled), RPA Writer автоматически захватывает объект исключения (включая вложенную цепочку `InnerException`) через псевдопеременную `$exception` и:

- если включена настройка **Auto-capture runtime exceptions** — сразу отправляет исключение в чат агенту для анализа;
- иначе сохраняет его как «последнее захваченное исключение», которое можно отправить в чат командой контекстного меню редактора кода или XAML-редактора **Send exception to RPA Writer**.

Повторные остановки на одном и том же исключении в течение 2 секунд не захватываются повторно.

## Как отправляется сообщение (что происходит «под капотом»)

1. Введённый текст + вложения формируют запрос.
2. Строится история (`transcript`) и системный промпт для выбранного режима.
3. `ContextAssembler` оценивает размер контекста; при приближении к лимиту — авто-сжатие (суммирование).
4. `AgentRunner` выполняет агентный цикл: при необходимости вызывает инструменты, передаёт их результат обратно модели и ждёт финального ответа.
5. Ответ выводится в чат; токены и стоимость обновляются в индикаторе контекста.
