# 15. Инструменты агента

В этой главе собраны все инструменты, которые агент может вызывать прямо в чате, а также правила,
по которым они становятся доступны. В отличие от кнопок интерфейса, эти инструменты вызываются
**самой моделью** (она сама решает, когда прочитать файл, выполнить команду или спросить уточнение),
а пользователь видит результат в ленте чата.

## Протоколы вызова (tool calling)

Расширение поддерживает два протокола передачи вызовов инструментов модели:

| Протокол | Настройка | Что происходит |
|---|---|---|
| **JSON over chat (compatible)** | `Tool calling` = *JSON over chat* | Модель отвечает обычным текстом с JSON-блоком вызова инструмента; расширение исполняет его и возвращает результат |
| **Native function calling** | `Tool calling` = *Native function calling* | Вызовы передаются в нативных полях `tool_calls` API OpenAI-совместимого провайдера |

Дополнительная настройка **Use 'tool' role for tool results** (`useToolRole`) определяет, какой ролью
помечаются результаты инструментов в транскрипте: `tool` (нативно) или `user` (совместимость с
провайдерами, не поддерживающими роль `tool`).

## Подтверждение вызовов (Ask before each tool)

Если включить настройку **Ask before each tool** (в панели **Permissions** вкладки Chat), то перед
каждым вызовом инструмента агент покажет карточку подтверждения: имя инструмента, категорию права,
признак «изменяет состояние» и краткий JSON аргументов. Пользователь одобряет (**Approve**) или
отклоняет (**Reject**) вызов. При отклонении модели возвращается пояснение, что инструмент пропущен.

Это удобно в Act-режиме, когда агент собрался что-то менять, и хочется контролировать каждый шаг.

## Правила доступности по режимам

| Режим | Доступные инструменты |
|---|---|
| **Plan** | Только read-only (не изменяют файлы/решение). Мутирующие инструменты скрыты и заблокированы |
| **Act** | Все инструменты, разрешённые правами |
| **Help** | Никаких инструментов — агент отвечает только по документации |

Каждый инструмент дополнительно привязан к категории права (см. [16. Права и политика чтения](16-permissions-and-security.md)):
если категория выключена в настройках, инструмент не показывается модели и не исполняется.

## Очередь сообщений

Под полем ввода чата находится очередь сообщений (**Message queue**). Когда во время активной беседы
пользователь вводит следующее сообщение, оно не отправляется сразу, а ставится в очередь.
После завершения текущего хода сообщение из очереди отправляется автоматически; его также можно
отправить вручную, не дожидаясь конца текущего хода. Очередь позволяет «забронировать» следующий
запрос, пока агент ещё работает над предыдущим.

## Resume task (продолжение после отмены)

Если прервать активный ход кнопкой **Cancel**, в футере чата появляется кнопка **Resume task**.
Она возобновляет прерванный запуск агента с той же итерации, не перестраивая историю и не повторяя
уже выполненные инструменты. Кнопка показывается только после ручной отмены (не при штатном
завершении или ошибке) и исчезает при старте нового хода, новой беседы или открытии другой беседы.

## Защита от зацикленных вызовов (stagnant loop)

Чтобы агент не тратил бюджет на бесконечный цикл, расширение отслеживает **повторяющиеся подряд
идентичные вызовы** (одно и то же имя инструмента с теми же аргументами). После `Max stagnant repeats`
одинаковых вызовов (по умолчанию `3`) вызов блокируется, и агенту возвращается заглушка-результат.

Если включена настройка **Nudge the model once before stopping a stagnant loop**, перед блокировкой
модели один раз отправляется подсказка сменить подход.

## Reasoning effort (глубина рассуждений)

Настройка **Reasoning effort** управляет тем, насколько «глубоко» модель думает перед ответом:

| Значение | OpenAI-совместимый провайдер | DeepSeek |
|---|---|---|
| Default | параметр не отправляется | параметр не отправляется |
| None | `reasoning_effort=none` | `thinking=disabled` |
| Minimal / Low | `minimal` / `low` | `low` |
| Medium | `medium` | `high` |
| High / Extra high / Max | `high` | `high` / `max` |

Провайдер определяется автоматически по Base URL и имени модели (наличие `deepseek`).

## Skills (навыки)

Навыки — это переиспользуемые слэш-команды/инструкции, которые агент выполняет через инструмент
`skills`. Каталог навыков задаётся настройкой **Skills directory** (вкладка Settings → RPA). Когда
запрос пользователя совпадает с одним из навыков, агент обязан вызвать инструмент `skills` перед
ответом. Аргументы навыка передаются строкой (`args`).

## Mermaid-диаграммы

Диаграммы Mermaid в ответах агента и в сгенерированных алгоритмах рендерятся встроенным
WebView2-рендерером (офлайн, через локальный `mermaid.min.js`). Поддерживаются flowcharts; тема —
тёмная. Ошибки синтаксиса диаграммы отображаются как текст ошибки в карточке сообщения.

## submit_and_exit (завершение)

Инструмент `submit_and_exit` завершает беседу финальным ответом. Агент обязан вызвать его только
после того, как убедился по собственным выводам инструментов, что результат корректен (файлы на
месте, содержимое соответствует формату, тесты/сборка прошли). `summary` — текст финального ответа,
`verified` — признак проверки результата.
