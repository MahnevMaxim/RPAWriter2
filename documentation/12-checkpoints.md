# 12. Чекпоинты (Checkpoints)

Чекпоинты — это автоматические снимки файлов рабочего каталога, которые RPA Writer делает в начале выполнения задачи и перед каждой правкой файла агентом. Они позволяют в любой момент сравнить текущее состояние с сохранённым (**Compare**) или откатить файлы к снимку (**Restore**).

## Как это работает

Снимки реализованы через изолированный «теневой» git-репозиторий (shadow repository):

- физически теневой репозиторий находится **вне** рабочего каталога: `%LocalAppData%\RPAWriter2\<17|18>\tasks\<TaskId>\checkpoints`;
- его `core.worktree` указывает на корень открытого решения, поэтому git работает с файлами решения, но все git-метаданные (объекты, ссылки, история) хранятся отдельно.

## Почему чекпоинты не конфликтуют с репозиторием робота

1. **Репозиторий робота не изменяется.** Все коммиты выполняются только в теневом репозитории; пользовательская история git робота (`.git` в корне решения) не трогается.
2. **Репозиторий робота не попадает в снимки.** Каталог `.git/` включён в исключения теневого репозитория (`.git/info/exclude`), поэтому снапшот не создаёт вложенный git-репозиторий.
3. **Изоляция git-окружения.** Перед каждым запуском `git.exe` расширение удаляет переменные окружения `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_CEILING_DIRECTORIES`, `GIT_TEMPLATE_DIR`, а также принудительно задаёт `commit.gpgSign=false` и служебные `user.name`/`user.email`.
4. **Физическое разделение.** Теневой репозиторий хранится в `%LocalAppData%`, а не внутри решения, поэтому репозиторий робота и git чекпоинтов не видят друг друга.

## Когда создаются чекпоинты

- в начале выполнения задачи — снимок с сообщением `task start`;
- перед каждой правкой файла агентом (инструменты записи/редактирования файлов) — снимок с сообщением `editor: <путь>`.

Чекпоинты создаются только при открытом решении; при отсутствии решения или выключенной функции снимок не делается.

В чате каждый новый снимок отображается индикатором: короткий хеш коммита, время и две кнопки:

| Кнопка | Что делает |
|---|---|
| **Compare** | Показывает изменения относительно этого чекпоинта (diff по изменённым файлам). |
| **Restore** | Спрашивает подтверждение и откатывает файлы к этому чекпоинту. Текущие несохранённые изменения перед откатом сохраняются в stash, чтобы откат всегда был обратимым. |

## Что исключается из снимков

В теневой репозиторий не попадают (см. `.git/info/exclude` теневого репозитория):

- `.git/`, `.vs/`, `bin/`, `obj/`, `node_modules/` и другие каталоги сборки/кэша;
- медиафайлы (изображения, аудио, видео);
- временные и кэш-файлы (`*.tmp`, `*.log`, `*.cache` и т.п.);
- большие/бинарные файлы и файлы баз данных (`*.zip`, `*.dll`, `*.exe`, `*.sqlite` и т.п.);
- шаблоны Git LFS из `.gitattributes` рабочего каталога (если такой файл есть);
- файлы, игнорируемые самим роботом через `.gitignore`.

## Ограничения (защита от конфликтов)

Чекпоинты **отключаются** (с сообщением об ошибке) в следующих случаях:

- в дереве решения найден вложенный git-репозиторий (`.git` в подкаталоге, отличном от корня решения) — «Checkpoints are disabled because a nested git repository was detected at: …»;
- теневой репозиторий был создан для другого рабочего каталога — «Checkpoints can only be used in the original workspace: …»;
- рабочая папка — домашняя директория пользователя, Desktop, Documents или Downloads.

## Настройка

Функция включается настройкой **Enable checkpoints (auto-snapshot files before edits)** в подвкладке **API → Агент** (по умолчанию включена). Подробнее: [Вкладка Settings](05-settings.md).

## Где хранятся данные

| Данные | Расположение |
|---|---|
| Теневые репозитории чекпоинтов | `%LocalAppData%\RPAWriter2\<17|18>\tasks\<TaskId>\checkpoints` |

История снимков хранится локально на компьютере и никуда не отправляется.
