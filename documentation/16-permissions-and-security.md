# 16. Права агента и политика чтения

Эта глава описывает, как ограничивается то, что агент может читать и менять: по-категорийные
права инструментов, политика доступа к файлам и защита секретов.

## Права агента (Permissions)

В правом нижнем углу вкладки Chat есть кнопка **Permissions**. Она открывает оверлей с категориями
прав инструментов:

| Право | Что разрешает | По умолчанию |
|---|---|---|
| **Read files** | Инструменты чтения файлов, поиска по коду, git_status/git_diff, списка файлов | вкл. |
| **Edit files** | Инструмент `editor` (правка/создание файлов) | вкл. |
| **Execute commands (PowerShell)** | Инструмент `run_commands` | выкл. |
| **Web fetch** | Инструменты `fetch_web_content` и `download_file` | выкл. |
| **MCP** | Инструменты MCP-серверов (см. [MCP-серверы](17-mcp.md)) | выкл. |
| **Ask before each tool** | Показывать карточку подтверждения перед каждым вызовом инструмента | выкл. |

Субагенты включаются отдельной настройкой **Enable sub-agents (spawn_agent)** во вкладке
Settings → API (по умолчанию выкл.); там же задаются лимиты:

- **Sub-agent max iterations** — максимум итераций субагента (по умолчанию `4`);
- **Sub-agent max depth** — максимальная глубина вложенности субагентов 1–5 (по умолчанию `2`).

Если категория права выключена, инструменты этой категории **не показываются модели** и не исполняются:
скрытый от модели инструмент невозможно вызвать.

## Политика чтения файлов

Инструменты чтения подчиняются политике путей (`ReadPathPolicy`), которая действует независимо от
режима:

### Read roots (разрешённые корни)

Агент может читать только файлы внутри разрешённых корней. По умолчанию корнями являются рабочие
каталоги текущего решения/проекта. Дополнительные корни добавляются в **Agent read scope (Plan mode)**
во вкладке Settings → General (кнопки **Add folder…** / **Remove selected**).

Если ни один корень не настроен, чтение запрещено (безопасно по умолчанию).

### Запрет служебных каталогов

Настройка **Deny service/build directories** (по умолчанию вкл.) блокирует чтение файлов внутри:

`bin`, `obj`, `.git`, `.vs`, `node_modules`, `packages`, `TestResults`, `.idea`, `.vscode`, `__pycache__`.

### Запрет секретных файлов

Настройка **Deny sensitive/secret files** (по умолчанию вкл.) блокирует чтение:

- `.env`, `web.config`;
- SSH-ключей: `id_rsa`, `id_dsa`, `id_ecdsa`, `id_ed25519` (и их копий с суффиксами);
- ключей и сертификатов: `*.pem`, `*.key`, `*.pfx`, `*.p12`, `*.snk`, `*.rdp`, `*.user`, `*.secret`;
- `appsettings*.json`;
- любых файлов, имя которых содержит `credential`, и файлов с префиксом `secrets`.

### Различие по режимам

| Режим | Доступ к чтению |
|---|---|
| **Plan / Help** | Строгая политика: только разрешённые корни, с запретом служебных каталогов и секретных файлов |
| **Act** | Полный доступ на чтение (агент уже работает над решением и может читать любые файлы) |

## Аудит безопасности роботов

Вкладка Spec → **Robot security audit** запускает статический анализ исходников робота на предмет
захардкоженных паролей и логинов. Режим выбирается в Settings → RPA (**Security audit mode**):

| Режим | Что проверяет |
|---|---|
| **Full (all areas)** | Полный анализ по всем областям |
| **Passwords & logins only** | Только пароли и логины |

Результат аудита выводится в области вывода вкладки Spec.

## Хранение секретов (API-ключ)

API-ключ не хранится в открытом виде: он шифруется средствами **DPAPI** (Windows Data Protection API)
и привязан к текущему пользователю Windows и машине. Остальные настройки, история чата и UI-состояние
разделены по открытому решению (см. [Диагностика и FAQ](09-troubleshooting.md) → «Где хранятся данные»).

## Автонастройка Visual Studio

При старте расширение автоматически применяет необходимые настройки редактора, чтобы не
конфигурировать их вручную на каждой машине:

- **Reload modified files unless there are unsaved changes** = включено (`AutoloadExternalChanges`);
- **Check for consistent line endings on load** = выключено (опция отсутствует в VS 2026 и потому
  пропускается без предупреждения).

Также при записи файлов нормализуются переводы строк (LF), а git-команды выполняются с
принудительным UTF-8 (см. [Git](02-chat.md)).
